# Evidence: milestones M3 to M5 (2026-10-30)

Host: Linux x86-64 (Debian 13), 32 logical CPUs, .NET SDK 10.0.403, runtime 10.0.14, LLVM/Clang/Flang 22.1.8. Commits are on the `m3-m5` branch, which starts from `m0-m2` at `0f21ada`. Every number below was produced by a command in this repository; licensed SPEC material is not included.

## What changed

- Portable mode (`dotnet64-v2`, now the default) compiles against and links unmodified musl 1.2.5, libc++/libc++abi 22.1.8 and flang-rt 22.1.8, built as LLVM bitcode by `scripts/build-sysroot.sh` into `sysroot/dotnet64-v2`. System mode links flang-rt built against glibc from `sysroot/system-linux-x64-v1`.
- The host layer (`src/LlvmNet.Runtime/Host/`, contract in `docs/dev/host-abi.md`) implements Linux system-call semantics over .NET.
- `managed-host` is removed (ADR-04). The hand-written C library, the C# Fortran runtime and MathNet.Numerics are deleted: `src/LlvmNet.Runtime` went from about 6,900 lines to 4,589, including the new host layer.

## Conformance

### musl libc-test (LC-19), `tests/libc-conformance.sh`

libc-test at commit `7b95dfa`, each test built with llvmnet in portable mode and statically against native musl 1.2.5; a test counts when it passes natively. Math tests check results in round-to-nearest without exception flags, the only floating-point environment CIL has.

| --- | ---: | ---: | ---: | ---: |
| api (header declarations) | 74 | 74 | 100% | 4 |
| functional | 67 | 60 | 89.6% | 4 |
| regression | 67 | 59 | 88.1% | 0 |
| math | 195 | 192 | 98.5% | 4 |

Every failure belongs to a documented limitation: no `fork`, `exec` or `vfork` (vfork, daemon-failure, execle-env, fflush-exit, pthread_exit-dtor, raise-race); no SysV IPC (ipc_msg, ipc_sem, ipc_shm) or sockets (socket); named semaphores, which musl publishes with a hard link (sem_open, sem_close-unmap); `sigaltstack`; asynchronous cancellation of a thread that is running code rather than blocked (pthread_cancel); the floating-point environment itself (math/fenv); `exp10l` and `pow10l`, where native musl uses x87 assembly and the portable build musl's generic C (2 ULP); and `%La` of unnormal x87 encodings (fpclassify-invalid-ld80).

The first run (before the fixes in `0609f39`) passed 53, 51 and 60 of the functional, regression and math tests; the fixes it prompted are listed in that commit.

### Fortran (FT-06), `tests/fortran-conformance.sh`

The NIST FCVS F77 suite and the `run` tests of the gfortran test-suite port in llvm-test-suite 22.1.8, each built natively with flang-22 and with llvmnet in portable mode. A test counts when the native build passes it: FCVS output equal to the reference, gfortran exit status 0 (or the expected failure for `xfail` tests). OpenMP, OpenACC, coarray, sanitizer, LTO and debugger directories are not run.

| Suite | Counted | Passed | Pass rate | Native failures (not counted) |
| --- | ---: | ---: | ---: | ---: |
| FCVS | 172 | 172 | 100% | 7 |
| gfortran run tests | 2,687 | 2,666 | 99.2% | 9 |

The 21 gfortran failures: 15 direct calls whose LLVM signatures differ from the callee's in ways the x86-64 calling convention tolerates but portable mode rejects (Flang's `-fdefault-integer-8` main calling `_FortranAProgramStart`, and `character(1)` or `logical` values passed to C; BE-39), 2 half-precision constants (BE-38), 1 coarray library, and 3 programs that end with an unexpected status (to be investigated). The first run counted 2,613 passes; mixed C and Fortran builds failed because the driver passed `-module-dir` to Clang, and complex multiplication and division needed compiler-rt builtins (LC-29), both fixed in `0ef8ad7`.

### libc++ (CX-08), `tests/libcxx-conformance.sh`

libc++'s own lit suite with a site configuration that compiles every test with `llvmnet-clang++` in portable mode (C++26, the libc++ test defaults) and runs it through `dotnet`; experimental features (the time-zone database) are off. 5,292 tests, 28 in parallel, about 25 minutes.

Classification of the 76 failures: 49 need locale data musl does not have (musl accepts any locale name and behaves as C.UTF-8, so libc++'s feature probes believe `fr_FR.UTF-8` and the others exist); 11 create FIFOs, Unix sockets or hard links (LC-30); 6 are death tests that fork; 2 use `-funsigned-char`, which the portable ABI rejects; 6 remain to investigate: `copy_file_large` (2 GB copy through libc++'s stream fallback), `remove_all` symbolic-link race (`toctou`, LC-30), thread-creation failure under resource limits, `jthread` join deadlock detection, and `sleep_for` interrupted by `SIGALRM` (no `alarm`/`setitimer`, LC-30).

Two runs before the final one found and fixed: libc++'s atomic-wait ABI depending on `__linux__` (the libraries now see the macros user code sees, ADR-14), `__MMX__` making libc++ size SIMD helpers to zero, directory symbolic links, `..` resolution, `EACCES` for refused paths and `readdir` types. Thread went from 83.8% to 99.4% and input.output from 91.6% to 97.2%.
