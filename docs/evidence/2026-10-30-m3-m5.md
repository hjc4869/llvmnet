# Evidence: milestones M3 to M5 (2026-10-30)

Host: Linux x86-64 (Debian 13), 32 logical CPUs, .NET SDK 10.0.403, runtime 10.0.14, LLVM/Clang/Flang 22.1.8. Commits are on the `m3-m5` branch, which starts from `m0-m2` at `0f21ada`. Every number below was produced by a command in this repository; licensed SPEC material is not included.

## What changed

- Portable mode (`dotnet64-v2`, now the default) compiles against and links unmodified musl 1.2.5, libc++/libc++abi 22.1.8 and flang-rt 22.1.8, built as LLVM bitcode by `scripts/build-sysroot.sh` into `sysroot/dotnet64-v2`. System mode links flang-rt built against glibc from `sysroot/system-linux-x64-v1`.
- The host layer (`src/LlvmNet.Runtime/Host/`, contract in `docs/dev/host-abi.md`) implements Linux system-call semantics over .NET.
- `managed-host` is removed (ADR-04). The hand-written C library, the C# Fortran runtime and MathNet.Numerics are deleted: `src/LlvmNet.Runtime` went from about 6,900 lines to 4,589, including the new host layer.

Every failure belongs to a documented limitation: no `fork`, `exec` or `vfork` (vfork, daemon-failure, execle-env, fflush-exit, pthread_exit-dtor, raise-race); no SysV IPC (ipc_msg, ipc_sem, ipc_shm) or sockets (socket); named semaphores, which musl publishes with a hard link (sem_open, sem_close-unmap); `sigaltstack`; asynchronous cancellation of a thread that is running code rather than blocked (pthread_cancel); the floating-point environment itself (math/fenv); `exp10l` and `pow10l`, where native musl uses x87 assembly and the portable build musl's generic C (2 ULP); and `%La` of unnormal x87 encodings (fpclassify-invalid-ld80).

The first run (before the fixes in `0609f39`) passed 53, 51 and 60 of the functional, regression and math tests; the fixes it prompted are listed in that commit. A rerun at `8bffee3`, after musl's `memcpy`, `memmove` and `memset` were routed to the runtime, gave the same counts (four jobs inside a memory-capped cgroup; see below).

### libc++ (CX-08), `tests/libcxx-conformance.sh`

libc++'s own lit suite with a site configuration that compiles every test with `llvmnet-clang++` in portable mode (C++26, the libc++ test defaults) and runs it through `dotnet`; experimental features (the time-zone database) are off. 5,292 tests, 28 in parallel, about 25 minutes.

| Directory | Passed | Failed | Death tests (need `fork`) | Unsupported | Pass rate |
| --- | ---: | ---: | ---: | ---: | ---: |
| std/containers | 1,807 | 0 | 3 | 7 | 100% |
| std/strings | 432 | 0 | 0 | 1 | 100% |
| std/algorithms | 276 | 0 | 0 | 35 | 100% |
| std/utilities | 1,372 | 4 | 1 | 29 | 99.7% |
| std/thread | 343 | 3 | 0 | 2 | 99.1% |
| std/localization | 283 | 47 | 0 | 3 | 85.8% |
| std/input.output | 589 | 16 | 2 | 37 | 97.4% |
| total | 5,102 | 70 | 6 | 114 | 98.6% |

Final run at `cb0e334` (8 jobs inside a memory cap; std/thread rerun after the timed-wait fix below). Failures now include tests that time out, which earlier summaries dropped (`join.deadlock`). Classification of the 76: 49 need locale data musl does not have (musl accepts any locale name and behaves as C.UTF-8, so libc++'s feature probes believe `fr_FR.UTF-8` and the others exist, and `get_money`/`put_money` use them); 12 create FIFOs, Unix sockets or hard links, or rely on race-safe `openat` (LC-30); 6 are death tests that fork; 2 use `-funsigned-char`, which the portable ABI rejects; and 7 remain: thread creation failure under resource limits (not expressible on .NET), `jthread` join deadlock detection (hangs), `sleep_for` interrupted by `SIGALRM` (no `alarm`), and four input/output and utilities tests still to investigate. `copy_file_large` passes since `sendfile` and `copy_file_range` exist (`9b9974a`).

This run also found that a timed condition wait could end up to a millisecond early: `Monitor.Wait` and `Thread.Sleep` count whole milliseconds, so `condition_variable::wait_for(250ms)` returned after 249.1 ms, libc++ reported no timeout, and the caller waiting for one waited forever (`wait_for` for `condition_variable` and `condition_variable_any`). Under the heavy load of the earlier runs the waits overslept and the tests passed. Futex waits and `nanosleep` now wait until their deadline has passed; `tests/host.sh` checks it.

Two runs before the final one found and fixed: libc++'s atomic-wait ABI depending on `__linux__` (the libraries now see the macros user code sees, ADR-14), `__MMX__` making libc++ size SIMD helpers to zero, directory symbolic links, `..` resolution, `EACCES` for refused paths and `readdir` types. Thread went from 83.8% to 99.4% and input.output from 91.6% to 97.2%.

### libc++abi (CX-13), `tests/libcxx-conformance.sh libcxxabi`

libc++abi's own lit suite, with the include paths of its static-library configuration, in portable mode; 81 tests, 22 unsupported (unwinder internals and native-only tests).

| Run | Passed | Failed | Pass rate |
| --- | ---: | ---: | ---: |
| First | 41 | 18 | 69.5% |
| After the fixes below | 52 | 7 | 88.1% |

The first run found four bridge bugs, all fixed: a `catch (...)` after a typed handler entered the typed one when that clause held the program's first type id, because both received selector 1 (5 catch tests, and `cxa_call_terminate`); an uncaught exception ended as an unhandled managed exception without calling `std::terminate`; `__cxa_uncaught_exception`, which libc++abi's `cxa_vector.cpp` calls, was missing (4 tests); and a program with more static fields than one CLR type may hold failed to load (`test_demangle`, tens of thousands of string literals). A regression test for the first also exposed that system mode's own catch matching handed pointer handlers the address of the thrown pointer, so `throw "text"` caught as `const char *` printed garbage; fixed. The 7 remaining failures are by design: the unwinder interface the CLR replaces (`_Unwind_Backtrace`, `_Unwind_ForcedUnwind`: 4), libc++abi's exception globals (`__cxa_get_globals`: 2), and termination without unwinding when no handler matches, which C++ leaves implementation-defined (`test_vector3`).
