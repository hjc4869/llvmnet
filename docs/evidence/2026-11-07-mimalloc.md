# Evidence: PF-25, mimalloc as the portable C library's allocator (2026-11-07)

Host: AMD Ryzen AI MAX+ 395 (Zen 5, 16 cores, 32 threads), 124 GB, Linux 6.12.115, .NET 10.0.14 (ILCompiler 10.0.14), clang, clang++ and flang 22.1.8. Branch `claude/mimalloc-a9521a` from `x264-perf` at `22a0f55`. Five other sessions ran gates, NativeAOT publishes and benchmarks throughout (load average 13 to 85), so every timing compares two builds that ran at the same time or alternately, pinned to a core each, each from a fresh copy of its files, and gives medians. The baseline is the same commit's toolchain with musl's mallocng (`artifacts/toolchain-base`, packaged from a worktree at `22a0f55`); "mimalloc" is this branch's toolchain (`artifacts/toolchain-mi`).

The owner decided on 2026-11-07 that mimalloc replaces mallocng ([decision](../plan/decisions.md#decided-by-the-owner-2026-11-07-pf-25)).

## The change

- **Source.** mimalloc 3.6.1, the newest release (2026-10-30), of the 3.x line its release notes recommend over 2.x ("stable legacy"): the release's own source archive, `mimalloc-v3.6.1-source.tar.gz`, whose SHA-256 the release page publishes, pinned in `scripts/sources.lock`.
- **Build.** `scripts/build-portable-mimalloc.sh`, a step of `scripts/build-sysroot.sh` right after musl, applies `ports/mimalloc/llvmnet.patch`, overlays the port's files and compiles all of mimalloc as one translation unit, `ports/mimalloc/llvmnet-libc.c` around mimalloc's `src/static.c`, into `mimalloc.o` in `libc.a`. `scripts/build-portable-libc.sh` leaves musl's allocator out: 1,336 musl sources instead of 1,348 (mallocng's six and `calloc.c`, `free.c`, `libc_calloc.c`, `lite_malloc.c`, `realloc.c`, `replaced.c` of `src/malloc`).
- **Memory from .NET only.** The primitive layer `ports/mimalloc/src/prim/llvmnet/prim.c` takes memory from two new host entry points in `src/LlvmNet.Runtime/Host/HostMemory.cs` ([host-abi.md](../dev/host-abi.md#entry-points)): `__llvmnet_memory_allocate(size, alignment)`, zeroed memory from `NativeMemory.AllocZeroed` aligned within an over-allocation, and `__llvmnet_memory_free(address)`, which frees such a block whole. They count against the limits mappings count against (`RLIMIT_AS`, `RLIMIT_DATA`, the memory .NET reports). The layer reports no virtual reservation, no partial free and no overcommit; commit, decommit, reset, reuse and guards succeed without effect, and a decommitted range keeps its contents (`needs_recommit` false), which mimalloc's commit bookkeeping allows. `calloc` was chosen over `NativeMemory.AlignedAlloc` because it is the one .NET allocation that guarantees zeroed memory, and the system's `calloc` leaves large blocks to lazily zeroed pages (as the `mmap` emulation already relies on), so mimalloc can treat fresh arenas as zero without touching them. `tests/allocator.sh` checks that `mimalloc.o` in the sysroot references `__llvmnet_memory_allocate` and none of `mmap`, `munmap`, `mremap`, `madvise`, `posix_madvise`, `mprotect`, `brk`, `sbrk` or `syscall`. Its other external references are musl's `clock_gettime`, `getentropy`, `getenv`, `getrusage`, `sysconf`, `write`, `sched_yield`, `__errno_location`, the pthread key and mutex functions, `stdout` and `stderr`.
- **The C library's names.** `malloc`, `realloc`, `free`, `malloc_usable_size` and musl's internal `__libc_malloc`, `__libc_realloc` and `__libc_free` are aliases of mimalloc's functions. The C names are weak and every other symbol of the object is internal (`opt -passes=internalize,globaldce`, which halves the object to 195 KB): the first libc-test run found `regression/flockfile-list`, which defines its own `malloc`, `calloc`, `realloc`, `free` and `aligned_alloc`, rejected with a duplicate definition of `calloc`, because in musl those are archive members of their own that a program's definitions keep out of the link; `tests/c/malloc-replace.c` now replaces the allocator and also defines `mi_malloc`, `mi_version` and `mi_option_get`, and matches native musl. `calloc`, `__libc_calloc` and `aligned_alloc` keep musl's argument checks, because mimalloc's release build returns null without setting `errno` for a `calloc` size that overflows and refuses an alignment of 0. `__malloc_donate` (called only by musl's dynamic linker) does nothing. musl's `posix_memalign`, `memalign`, `valloc` and `reallocarray` stay and call `aligned_alloc` and `realloc`. C++'s `operator new` and `delete` stay libc++abi's, which call `malloc` and `free`. A failing allocation sets `errno` to `ENOMEM` as musl's does: mimalloc's default error handler sets it only when it is still 0, so the layer registers one that always does.
- **Configuration.** Release (`NDEBUG`), `MI_LIBC_MUSL`, no heap profiler (`MI_PROFILE=0`, which would bring stdio into every program), no fork handler, no weak `std::get_new_handler`, `-O2` without the vectorizers like the other runtime libraries. `__x86_64` is undefined while compiling: llvmnet defines it, and mimalloc would then size its page map for x86-64's 47-bit user addresses, while portable images also run where .NET hands out 48-bit ones (Linux ARM64). `purge_delay` defaults to -1, because a purge cannot return memory to .NET. The other choices were measured (below).
- **Patch.** `llvmnet.patch` has two hunks: the primitive layer's selection in `src/prim/prim.c`, and an empty `asm` statement left out of the allocation fast path in `src/alloc/alloc.c` (below).

## Choices measured on the malloc/free benchmark

`tests/perf/malloc.c` (20 million `malloc`/`free` pairs of 16 to 4,096 bytes over 4,096 live slots) as NativeAOT, pinned to CPU 8, nine alternating runs each from a fresh copy (`abtime.py`, medians), all four before the fence below was removed:

| Build | Time | Against the page map at `-O2` |
| --- | --- | --- |
| mallocng (baseline) | 1.345 s | 3.13 |
| mimalloc with 256 MiB-aligned page metadata (mimalloc's default) | 0.532 s | 1.24 |
| mimalloc with the page map (`MI_FREE_USE_PAGEMAP`), `-O2` | 0.430 s | 1.00 |
| the same at `-O3` | 0.436 s | 1.01 |

- **The page map.** mimalloc's default places page metadata at 256 MiB-aligned addresses so that `free` finds it by masking the pointer. On an `mmap` system the over-allocation is trimmed to the alignment; a block from the host can be freed only whole, so a 256 MiB arena took a 512 MiB block (and counted as such against `RLIMIT_DATA`, and against commit on Windows), and the direct allocation mimalloc falls back to when no arena fits needed the same alignment: a program that set `RLIMIT_DATA` to 300 MiB could allocate 3 MiB in 100 KB blocks. With the page map, arenas need 64 KiB alignment, `free` is faster as well, and under low limits mimalloc takes smaller arenas and then single pages (table below).
- **`-O3`** measured the same as `-O2`, so mimalloc stays at the sysroot's `-O2`.

Allocation under limits the program sets itself, in 100 KB blocks until `malloc` fails, then one 16-byte `malloc` (`-fno-builtin`, JIT; `RLIMIT_AS` gave the same numbers):

| `RLIMIT_DATA` | mallocng | mimalloc, aligned metadata | mimalloc, page map |
| --- | --- | --- | --- |
| 16 MiB | 15 MiB, then 16 bytes succeed | 0 MiB, fails | 6 MiB, succeeds |
| 64 MiB | 62 MiB, succeeds | 0 MiB, fails | 48 MiB, succeeds |
| 300 MiB | 292 MiB, fails | 3 MiB, fails | 247 MiB, succeeds |
| 1,000 MiB | 976 MiB, fails | 322 MiB, succeeds | 837 MiB, succeeds |

## The fence on every malloc

The first omnetpp profile with mimalloc (below) had 19% of `mi_malloc`'s samples on the instruction after `lock or dword ptr [rsp], 0`, a full memory barrier in the allocation fast path. Its source is `__asm("" : : "r"(xused) : )` in `mi_page_malloc_zero`, an empty statement that makes GCC load a field before a test. llvmnet translates every `asm` statement without instructions or outputs to `Thread.MemoryBarrier()` (`FunctionEmitter.Call`), which is right for `asm volatile("" ::: "memory")` but not needed without a memory clobber. The patch leaves this one statement out for portable builds; mimalloc's bitcode has no `asm` left. Translating an empty `asm` without a `memory` clobber to nothing would be the general fix, in the compiler.

## Threads

Portable threads are musl's pthreads on managed threads. mimalloc keeps its default and cached heap pointers and its thread id in C thread-locals, which llvmnet gives every thread (the thread id is the address of one, mimalloc's portable fallback: llvmnet defines no `__x86_64__`, so mimalloc reads no thread-pointer register), and detects thread exit with a pthread key whose destructor calls `_mi_thread_done`, as on Unix.

`tests/c/malloc-threads.c` runs 4,000 short-lived threads, 32 at a time, each allocating 64 blocks of 1 byte to 3 MB, growing every fourth with `realloc`, clearing with `calloc`, aligning with `aligned_alloc` (16 bytes to 4 KB), freeing most and handing 8 to the main thread, which checks and frees them after the thread has exited (half the threads end with `pthread_exit`); then 4 producers and 4 consumers pass 200,000 blocks through a bounded queue, so most frees are on another, running thread; then 1,024 threads whose thread-specific data destructor frees its value and allocates and frees again while the thread exits; then 8 detached threads that keep allocating while `main` returns. The output equals native musl's under the JIT and as NativeAOT (`tests/allocator.sh`; 3 of 3 NativeAOT runs). mimalloc's statistics of the NativeAOT run (`MIMALLOC_SHOW_STATS=1`): 6,000 thread heaps created and 9 left at exit (the main thread and the 8 detached threads), 83,100 pages abandoned by exiting threads, none left abandoned, 63,000 reclaimed by other threads. `tests/c/thread-stress.c` (10,000 threads, in `tests/musl-behavior.sh`) also matches native musl.

A program that starts 100,000 threads one after another, each allocating and freeing a block, kept its peak resident size at 70 to 73 MiB (mallocng 69 to 77 MiB), and used the same processor time (4.4 s against 4.6 s for 40,000 threads under the JIT; wall time followed the host's load).

`fork` stays `ENOSYS`, and mimalloc registers no fork handler (`MI_NO_PTHREAD_ATFORK`). A thread that a host library started and that calls the program back through a native extension (NX-08) runs no key destructors when it ends, so its heap is never released and its pages are not reclaimed; such threads are rare (one per host callback thread) and the memory is the thread's own blocks. A .NET thread that runs a signal handler borrows the main thread's musl thread pointer, but its thread-locals are its own, so it gets a heap of its own rather than the main thread's.

## Native baselines

`artifacts/mimalloc-native/` in the main checkout (gitignored) holds the same release built with `clang-22 -O3` as a static override, for the native SPEC and x264 baselines: `lib/mimalloc.o` (mimalloc's `MI_BUILD_OBJECT`, `MI_OVERRIDE=ON`, CMake `Release`, `MI_PROFILE=OFF` to match the portable build) and `lib/libmimalloc.a`, `build.sh`, which rebuilds them from the pinned archive and runs the checks, and a README that says how to link them (the object with the program's objects; for SPEC, `EXTRA_LIBS = .../lib/mimalloc.o`) and how to verify the replacement. `verify/verify.c` and `verify/verify.cpp` check with `mi_is_in_heap_region` that memory from `malloc`, glibc's own `strdup`, `getline`, `posix_memalign` and `asprintf`, and C++'s `new`, `new[]`, aligned `new`, `std::string` and `std::vector` all comes from mimalloc; both print `replaced`, also with the archive linked through `--whole-archive`, and a Fortran program linked with `flang-22` reports mimalloc's start under `MIMALLOC_VERBOSE=1`. What still differs from the portable build is what each gets from its platform: natively, mimalloc reserves 1 GiB arenas with `mmap`, purges unused ranges after 1 s with `MADV_DONTNEED` (`MIMALLOC_PURGE_DELAY=-1` gives the portable policy), and `operator new` is mimalloc's own.

## System mode

System mode is unchanged and needs no change: a system-mode program calls the host C library's `malloc`, glibc's, through its generated host bridge (`libprogram.llvmnet-host.so` imports `malloc@GLIBC_2.2.5`, `free`, `malloc_usable_size`), and shares that allocator with the native libraries it calls, which free what they allocate with it.
