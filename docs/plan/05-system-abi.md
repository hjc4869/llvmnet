# Workstream SA: System ABI and native interoperability

Prefix `SA`. Owner: unassigned. Milestone: [M7](README.md#m7-toolchain-and-distribution) for P0/P1 items; the mode is already functional.

## Current state (verified 2026-10-30)

- `--runtime=system` (`system-linux-x64-v1`) links translated code against the real glibc, libm and user libraries through LLVM-generated per-signature native bridges (`HostInterop.cs`, `native/abi.cpp`), unmanaged-callable thunks for C callbacks, native pthreads with managed-entry/TLS adapters, and a static native input for NativeAOT. All installed SPEC entries validated in this mode.
- Explicit limits: native code cannot invoke translated variadic or aggregate callbacks; external native TLS globals need a bitcode definition; foreign-thread TLS teardown, `pthread_exit`/cancellation and hardware-fault signal recovery are incomplete; native C++ ABI interchange is a non-goal. The older `--native-import` scalar P/Invoke path was removed on 2026-10-31 (SA-01); `--system-library` is the one native path.

## Items

- [x] **SA-01** (S, P0) Decide the fate of `--native-import` (legacy scalar P/Invoke): fold its use cases into `--system-library` or keep it as a documented escape hatch; remove dead paths accordingly ([ADR-04](decisions.md#adr-04-retire-managed-host-mode)). — **Decided** (2026-10-31, ADR-04): remove it; the option fails with guidance pointing at `--system-library`. — **Done** (2026-10-31): the P/Invoke emission, the import table and the two fixtures are deleted; `--native-import` fails with "was removed (ADR-04, SA-01)" and the guidance (`tests/modes.sh`, `DriverTests`); evidence in [evidence/2026-10-31-m7-toolchain.md](../evidence/2026-10-31-m7-toolchain.md#sa-01---native-import-removed).
- [ ] **SA-02** (M, P1) Native invocation of translated aggregate and variadic callbacks: generate LLVM thunks that unpack native registers into the software argument record (the inverse of the call bridge). Motivating cases: `qsort` with struct elements through native libc, libxml2 variadic error callbacks, OpenMP outlined functions with struct arguments.
- [ ] **SA-03** (M, P1) External native TLS globals resolved through generated per-thread accessors (`dlsym` plus `__tls_get_addr`), or a link-time diagnostic naming the symbol.
- [ ] **SA-04** (M, P1) Foreign threads (created by native libraries) calling translated callbacks: lazy runtime attach, TLS initialization, destructor ordering; test with a native pthread pool calling back into translated code under JIT and NativeAOT.
- [ ] **SA-05** (M, P1) `pthread_exit`, cancellation points and `pthread_cleanup_push` across managed frames: implement what the CLR permits and reject the rest at link time where detectable.
- [ ] **SA-06** (M, P1) Signals in system mode: real `sigaction` handlers with a trampoline into translated code and the documented restrictions; memory-fault recovery documented as impossible.
- [ ] **SA-07** (M, P1) Deployment: decide whether the JIT sidecar `.llvmnet-host.so` is embedded as a resource and extracted at startup or required alongside the image; document RPATH and `--system-library` copying; NativeAOT keeps static linking. — **Decided** (2026-10-31): the sidecar ships next to the image in the payload folder and is found by a fixed relative path, with no embedding or extraction. Documentation open.
- [ ] **SA-08** (S, P1) ABI tag `system-linux-x64-v1` stays; a Linux ARM64 system ABI requires a bridge port and is post-1.0 ([XP](07-cross-platform.md)).
- [ ] **SA-09** (M, P1) Bridge fuzzing: random C signatures (struct sizes 1 to 64 bytes, mixed float/integer members, varargs with long double) compiled natively and through the bridge, comparing results; stored as a nightly job.
- [x] **SA-10** (M, P1) `fork()` followed by `exec` (found by the [library survey](../evidence/2026-11-02-library-survey.md), 2026-11-02): the classic child-process pattern loses the child's redirected descriptors and often hangs the parent, and ANGLE's test runner aborts with "stack smashing detected"; neither the limitation nor a diagnostic exists today. Make the fork-to-exec window safe or make `fork` fail with `ENOSYS` as in portable mode, and document it. Done when the reproducer runs as native or fails cleanly. — **Done** (2026-11-02, `c7d030b`): the cause is CoreCLR's W^X, which maps generated code from shared memory that a forked child keeps writing into with its parent. `fork`, `vfork`, `_Fork` and `forkpty` fail with `ENOSYS` while generated code is shared (the JIT's default); NativeAOT executables and the JIT with `DOTNET_EnableWriteXorExecute=0` call the host's `fork`, and `vfork` behaves as `fork`. The reproducer fails cleanly under the JIT and runs as native otherwise; [modes.md](../user/modes.md) documents it and `tests/system-fork.sh` covers it. Evidence: [2026-11-02-system-mode-survey.md](../evidence/2026-11-02-system-mode-survey.md).
- [x] **SA-11** (S, P1) The optional libstdc++ archive (`scripts/build-system-cxx.sh`) has no `src/c++20` members, so C++20 `std::stringstream::str()` is unresolved (found by the [library survey](../evidence/2026-11-02-library-survey.md)). Done when the reproducer links and runs with `-std=c++20`. — **Done** (2026-11-02, `427c322`): `scripts/build-system-cxx.sh` compiles libstdc++'s `src/c++20` as `libstdc++.so` has it, plus C++17's floating-point `to_chars` and `from_chars`; the reproducer links and runs with `-std=c++20`, and `tests/system-cxx.sh` runs `std::format`, atomic waits, time zones and `osyncstream` as C++20 and C++23. Evidence: [2026-11-02-system-mode-survey.md](../evidence/2026-11-02-system-mode-survey.md).
- [x] **SA-12** (S, P1) System mode predefines `__SSE2__`, so libraries select SSE intrinsic paths that fail only at the final link ("Unsupported intrinsic: llvm.x86.sse2.psad.bw"; ANGLE's abseil and astc-encoder, found by the [library survey](../evidence/2026-11-02-library-survey.md)). The choice between not advertising SSE and translating the common SSE2 intrinsics is [proposed for the owner](decisions.md#decided-by-the-owner-2026-11-02-library-survey); either way the failure becomes a compile-time diagnostic. — **In progress** (2026-11-02, `07aa18e`): compiling a unit with an untranslated x86 intrinsic now warns, naming it and its function, and the link error names it with the way out (`-U__SSE__ -U__SSE2__`); `_mm_pause` and the SSE fences translate. The macro choice is still the owner's; the evidence recommends not predefining them (option b). Evidence: [2026-11-02-system-mode-survey.md](../evidence/2026-11-02-system-mode-survey.md#recommendation-on-the-macros). — **Note** (2026-11-03): option (c), translating the common SSE2 intrinsics, is Level 2 of [12-simd.md](12-simd.md) (SV-08) with host-instruction dispatch rather than scalarization; option (b) stays a separate owner decision ([ADR-16](decisions.md#adr-16-simd-levels)). — **Note** (2026-11-04, SV-08): option (c) is done: system mode translates the SSE to SSE4.2 intrinsics, so the predefined `__SSE2__` selects paths that link and run (astc-encoder, Chromium zlib and abseil from the survey, [evidence](../evidence/2026-11-04-x86-intrinsics.md#the-surveys-reproducers)); keeping the macros, and so closing this item, is [proposed for the owner](decisions.md#decided-by-the-owner-2026-11-04-sv-08). — **Done** (2026-11-05, decided by the owner): system mode keeps predefining `__SSE__` and `__SSE2__`, as native x86-64 does; the SSE to AVX2 intrinsics translate (SV-08, SV-09), and AVX-512 and later warn while compiling and fail at the link when reached.
- [x] **SA-13** (S, P1) Narrow integers through native function pointers and callbacks (found while testing NX-03, 2026-11-03): a call through a pointer to native code passed `uint8_t`, `int8_t` and `int16_t` arguments without the extension their `signext` or `zeroext` attribute asks for, which clang's optimized callees rely on, and kept the undefined upper bits of a narrow result, so `int32_t (*)(uint8_t, int16_t, uint32_t)` from `dlsym` returned 65790 for `255, -1, 0` instead of 254 and a `uint8_t` result read as 511; a translated callback that native code called with a signed narrow argument received it sign-extended, where llvmnet keeps narrow integers zero-extended (`(uint16_t)half` was 4294967295). Direct calls through the generated bridges were right. — **Done** (2026-11-03): the native branch of an indirect call loads narrow arguments again, extended as their call-site attribute says, and masks a narrow result (`FunctionEmitter`); the callback entry masks narrow parameters (`HostInterop.Callback`). `tests/system-abi.sh` checks both directions against its native library, now built at `-O1` so the callee relies on the caller (master fails both checks), and `tests/extensions.sh` compares system mode in full again.
