# Workstream PF: Performance

Prefix `PF`. Owner: unassigned. Milestone: [M8](README.md#m8-performance). Correctness gates always take precedence; no item here may replace an unsupported operation with a stub.

## Current state (verified 2026-10-30, from `docs/dev/video-benchmark.md` and `docs/user/limitations.md`)

- Four-thread 4K HEVC decoding under JIT: portable SIMD128 profile at 2.49x the elapsed time of the installed native ffmpeg (which uses hand-written assembly); scalar portable at about 2.8x. An earlier single-thread full-file run measured 1.32 to 1.36x native built from the same bitcode.
- NativeAOT with the baseline instruction set regresses the SIMD profile 2.2x against scalar AOT; host-targeted AOT gains about 15%. The cause has not been established.
- Known structural costs: the global atomics lock, heap-backed scoped allocas, unbuffered `printf`, per-operation `ConcurrentDictionary` lookups in pthread mutex/condition operations, software varargs records, exception-based `setjmp`, and JIT MinOpts fallback for very large methods.

## Items

- [x] **PF-01** (M, P0) Benchmark harness and baselines: nightly runs of ffmpeg `bench` mode on redistributable clips, free workloads from `llvm-test-suite` (and the SPEC-like zstd/x264 sources where licenses allow), and microbenchmarks (`malloc`, `fwrite`, atomics, `calli`, varargs, `Float80`, `memcpy`), with results tables in `docs/evidence/` and regression thresholds that fail the nightly. — **Done** (2026-11-01, `scripts/benchmark.py`): 58 benchmarks (11 microbenchmarks, 42 `llvm-test-suite` programs, ffmpeg HEVC and H.264 at one and four threads, startup) against native, JIT geomean 2.42x and NativeAOT 1.72x; baseline `tests/perf/baseline.tsv`, regressions above 25% per benchmark or 10% geomean fail the nightly job; set, thresholds and zstd/x264 proposed for the owner; the first GitHub run waits for FD-19. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-01-benchmark-harness-and-baselines).
- [x] **PF-02** (M, P0) Atomics ([BE-16](01-compiler-backend.md)) and musl futex-based mutexes measured on the threaded ffmpeg case; expected to remove the serialization visible at four threads. — **Done** (2026-11-01): the four-thread decode is not serialized by locks (NativeAOT scales 2.7x and 3.3x like native; futex code is 2.3% of CPU); the JIT's shortfall is startup and compilation. Futexes now use hashed buckets of per-thread waiters with exact wake counts and real requeue, and aligned 32/64-bit atomics are emitted inline: mutex microbenchmark 2.34x to 1.37x native, atomics 1.94x to 1.20x (NativeAOT at native speed), ffmpeg unchanged. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-02-atomics-and-futex-based-mutexes-on-the-threaded-ffmpeg-case).
- [x] **PF-03** (M, P1) stdio: buffered musl I/O replaces per-call host writes; measure host-call cost and choose buffer defaults. — **Done** (2026-11-01): a host call costs 30 to 90 ns more than the kernel's under the JIT and less as NativeAOT; streams get 4,096-byte buffers (glibc's `st_blksize` size, so flushes happen where native builds flush) instead of musl's 1,024, and `long double` comparisons no longer build `BigInteger` values: fwrite 2.39x to 1.83x native (JIT) and 2.11x to 1.41x (NativeAOT), printf 6.45x to 5.23x. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-03-stdio-buffers-and-the-cost-of-a-host-call).
- [x] **PF-04** (M, P1) Alloca arena ([BE-17](01-compiler-backend.md)) measured on recursion-heavy code (deepsjeng, perlbench). — **Done** (2026-11-01): translated methods no longer zero locals and `localloc` blocks (`localsinit` off), and scoped allocas use a per-thread bump arena instead of a `StackMemory` object and a heap block per alloca: ffmpeg H.264 3.20x to 2.20x native (JIT) and 2.23x to 1.46x (NativeAOT), varargs 4.54x to 3.44x, deepsjeng 3 to 5% faster; perlbench not measured (needs the SPEC harness build). Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-04-allocas-without-zeroing-and-an-arena-for-scoped-allocas).
- [x] **PF-05** (M, P1) Indirect calls: measure `ldftn`/`calli` against delegate and function-pointer-table alternatives on x264 and ffmpeg DSP dispatch. — **Done** (2026-11-01, measurement; no change): `calli` through an address table is the fastest polymorphic dispatch (8.0 ns per call under the JIT, 7.0 as NativeAOT, against 12.8 and 8.5 for delegates and 14.3 and 9.1 for interfaces); the ffmpeg decodes make 9 to 24 million indirect calls, at 0.5 ns over a direct call 5 to 12 ms of 3-second decodes. x264 is not in the benchmark set. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-05-indirect-calls).
- [ ] **PF-06** (L, P1) JIT code quality: inspect hot kernels with `DOTNET_JitDisasm`, remove avoidable `UInt128` and normalization masks, tune `TieredPGO`/`TieredCompilation` settings in the emitted `runtimeconfig.json`, and evaluate ReadyToRun for startup ([TC-08](06-driver-and-toolchain.md)). — **In progress** (2026-11-01): 32- and 64-bit funnel shifts and rotates are emitted as `BitOperations` intrinsics or width-specific helpers (salsa20 1.66x to 1.11x native under the JIT, 8.0x to 1.05x as NativeAOT); dynamic PGO is off in the emitted `runtimeconfig.json` (6.6% faster over 24 benchmarks; tiered compilation off was 8.4% faster but cost 22 ms of start-up); ReadyToRun evaluated under PF-10 (3 ms, linux-x64 only) and not adopted. Open: a systematic `DOTNET_JitDisasm` review of hot kernels and the `UInt128` and normalization masks. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-06-jit-code-quality).
- [ ] **PF-07** (L, P1) Over-limit methods ([BE-25](01-compiler-backend.md), [BE-26](01-compiler-backend.md)): quantify the MinOpts penalty on SPEC gcc and perlbench, then outline. — **Measured, open** (2026-11-01): in the free benchmark set only ffmpeg's H.264 decoder runs hot code as MinOpts under the JIT (CABAC decoding, the deblocking filter, macroblock reconstruction: 58 to 167 KB of IL each); the release JIT's limits are constants (the `DOTNET_JITMinOpts*` settings have no effect), NativeAOT never falls back, and H.264's JIT-to-NativeAOT gap (1.51) against HEVC's (1.19) puts the penalty at about a fifth of the JIT's H.264 time. SPEC gcc and perlbench were not measured; outlining is BE-26 (L) and not started. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-07-over-limit-methods).
- [x] **PF-08** (M, P1) NativeAOT instruction sets: explain the baseline SIMD regression (hypotheses: non-constant shuffle indices or widening operations without hardware support under the baseline ISA), add `x86-64-v3` as an explicit middle option, document the trade-offs; keep baseline as the default. — **Decided** (2026-10-31): baseline stays the default; `x86-64-v3` is an explicit opt-in. — **Done** (2026-11-01): the default is ILC's `x86-64` level, where `Vector128.Shuffle` with run-time indices has no `pshufb` and runs in software (3 to 5 times slower); widening is unaffected. `--aot-instruction-set x86-64-v3` added (x64 targets only): the SIMD128 HEVC decode goes from 3.29 s to 2.68 s, level with scalar; documented in `docs/user/simd128.md`; a v2 default for SIMD128 builds is proposed for the owner. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-08-nativeaot-instruction-sets).
- [ ] **PF-09** (L, P2) General vector lowering ([BE-32](01-compiler-backend.md)). Post-1.0.
- [x] **PF-10** (S, P1) Startup latency of `dotnet program.dll` hello-world and of NativeAOT binaries; trim the runtime assembly; `InvariantGlobalization` where safe. — **Done** (2026-11-01): NativeAOT starts in 2 ms like native; the JIT in 36 ms (from 39) against a 17 ms floor for any `dotnet program.dll`, after the start-up path stopped instantiating LINQ (194 to 134 JIT compilations before `main`). Invariant globalization breaks IANA time-zone names on Windows, so the JIT keeps ICU and NativeAOT projects now drop it only for non-Windows targets (win-x64 executables had resolved `Europe/London` to UTC). ReadyToRun (3 ms on linux-x64 only) is left to PF-06. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-10-startup-latency).
- [x] **PF-11** (M, P1) Memory: RSS versus native (330 MB versus 251 MB on the video test), GC configuration for non-GC workloads, large-page arenas for musl `malloc`. — **Done** (2026-11-01, measurement): NativeAOT stays within 7 to 12 MB of native; the JIT adds the runtime (28 MB) and its generated code (60 to 150 MB for Bullet and ffmpeg). GC settings change nothing, because translated programs keep their data in native memory; the JIT's tiering does (TieredPGO off saves 20 MB on ffmpeg, left to PF-06), and `malloc` is already faster than glibc's, so no arena work. The harness's peak RSS, which counted its own 27 MB, now comes from GNU time. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-11-memory).
- [x] **PF-13** (S, P1) Every function-pointer materialization calls `SystemAbi.RegisterCallback`, a concurrent dictionary insert, even in portable mode where the identity is the method pointer itself. Register once per function, or not at all in portable mode. — **Done** (2026-11-01): the module initializer registers each address-taken function once and the address is a single `ldftn`; the callback microbenchmark went from 1.98x to 1.31x native under the JIT and to native speed as NativeAOT, startup unchanged. Evidence: [2026-11-01-m8-performance.md](../evidence/2026-11-01-m8-performance.md#pf-13-register-callbacks-once).
