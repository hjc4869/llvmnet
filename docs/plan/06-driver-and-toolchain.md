# Workstream TC: Driver, toolchain, packaging and documentation

Prefix `TC`. Owner: unassigned. Milestone: [M7](README.md#m7-toolchain-and-distribution).

## Current state (verified 2026-10-30)

- `Driver.cs` parses options in a hand-written loop of about 100 cases; unknown `-` options are forwarded to Clang/Flang, `-Wl,` options other than `--version`/group markers are rejected. Aliases `llvmnet-clang`, `llvmnet-clang++`, `llvmnet-flang` select the frontend by executable name. Defaults are `-O1 -fno-vectorize -fno-slp-vectorize`; `-c` rejects `.ll`/`.bc`/`.o` inputs. — Since 2026-10-31 (TC-01) the options are a table in `DriverOptions.cs` with four treatments per mode, and `--help` and `docs/user/driver.md` are generated from it.
- Outputs: `.dll` with `runtimeconfig.json` and copied runtime assemblies; a Unix launcher plus `<name>.llvmnet/` payload; or a NativeAOT executable produced by generating a `NativeHost.csproj` and running `dotnet publish`. Windows launchers do not exist.
- `scripts/package-toolchain.sh` builds a relocatable tree, optionally bundling LLVM (about 638 MiB; 533 MB since TC-13); `tests/deployment.sh` proves compilation with no `dotnet`/`clang`/`flang` on `PATH`. NativeAOT still needs the SDK and a native linker (checked up front since TC-12).
- `cmake/llvmnet.cmake`, `meson/llvmnet.ini` and `config/spec/llvmnet.cfg` exist and are exercised by the dependency and SPEC builds.
- Documentation is accurate but is written as dated engineering evidence (`status.md`, `spec-coverage.md`, `toolchain.md`) rather than user documentation. — Restructured on 2026-10-31 (TC-16) into `docs/user/`, `docs/dev/` and `docs/evidence/`.

Done when a large link costs about what loading and translating its bitcode costs, measured on cjxl and DM. Every translated program is byte-identical to before. Evidence: [2026-11-02-link-scaling.md](../evidence/2026-11-02-link-scaling.md).
