# Workstream JP: CIL shaped for RyuJIT

Prefix `JP`. Owner: unassigned. Milestone: [M12](README.md#m12-cil-shaped-for-ryujit), proposed 2026-11-04; its placement before or after 1.0 is the owner's decision. The decision this workstream depends on is [ADR-17](decisions.md#adr-17-readytorun-for-jit-deployments) (Proposed), which only JP-06 and JP-10 need. The other items change the CIL and `runtimeconfig.json` llvmnet emits, and keep the image one platform-neutral file.

The owner asked whether CoreCLR's JIT (RyuJIT, .NET 10 and 11) is tuned for particular shapes of IL, and whether llvmnet can emit those shapes. It is, in three ways that matter for translated C and C++. There are hard per-method limits, past which the JIT stops optimizing or inlining. A few IL forms compile much better than their equivalents. And the tiering policy assumes programs that stop calling new methods soon after start-up. The reading of the JIT's sources and the experiments behind this page are in [evidence/2026-11-04-jit-patterns.md](../evidence/2026-11-04-jit-patterns.md).

## Current state (verified 2026-11-04)

Sources read: dotnet/runtime `main` at `7f4a969` (2026-11-02, the branch after `release/11.0`), `src/coreclr/jit` and the VM's tiering and JIT interface. Runtimes measured: 10.0.14 and 11.0.0-rc.2.26504.105 on the build host (Zen 5, 32 threads), crossgen2 and ILCompiler 10.0.14.

- **Tiering delay.** Call counting, and so promotion to Tier1, waits until 100 ms pass in which no method is called for the first time (`tieredcompilation.cpp`). Translated programs keep calling new functions, so call-heavy code stays at Tier0 far longer than the delay. `System.Runtime.TieredCompilation.CallCountingDelayMs` is a `runtimeconfig.json` property in both runtimes, and PF-06 did not try it. Setting it to 0 makes bullet 24% faster, functionobjects 20%, tramp3d 27%, lame 43% and ffmpeg's H.264 decode 12%.
- **Per-method limits.** In release builds RyuJIT compiles a method with MinOpts when it has more than 60,000 bytes of IL, 20,000 IL instructions, 2,000 basic blocks, 2,000 locals or 8,000 local references (`compiler.cpp`, `DEFAULT_MIN_OPTS_*`). The limits are constants; the `JITMinOpts*` settings exist only in debug builds. AOT compilation (NativeAOT and ReadyToRun) never falls back. Below MinOpts there are softer limits. Locals past `JitMaxLocalsToTrack` (1,024) are untracked and never get a register. Inlining into a method stops once it has 90% of that, 921 locals (`fginline.cpp`), and so does struct promotion. CSE takes at most 64 candidates per method.
- **What llvmnet hits.** In ffmpeg's decode harness, 49 of 7,535 translated methods trip a MinOpts limit, 48 of them on the instruction count, and 150 have at least 921 locals, so nothing is inlined into them. H.264's CABAC decoder, both deblocking filters, slice setup, macroblock reconstruction, direct prediction and error concealment run as MinOpts code (58 to 169 KB of IL each). A Tier1 recompilation of such a method falls back to MinOpts again and is discarded (`tieredcompilation.cpp`), so the JIT compiles each of them twice; compiling them once saves 3.7% of the decode. BE-33's local sharing (in the working tree, not yet committed) removes the local-count problems. Translated with it, 26 decoder methods are still over a limit, against the 16 that `--diagnose-limits` reports (BE-46). The triggers are now local references (25 methods, unchanged by sharing), the instruction count (21) and IL size (17).
- **`static readonly` is a constant.** In optimized code, an `initonly` static field of an initialized class is read at compile time and becomes an immediate (`impImportStaticReadOnlyField`, `getStaticFieldContent`). llvmnet's global and constant addresses (`__global*`, `__constant*`) are plain static fields. Each access is therefore a load, which the JIT cannot hoist past a store through a pointer. This is PF-17's reload.
- **`switch`.** RyuJIT turns the CIL `switch` instruction into a jump table or a bit test. From compare chains, it rebuilds a switch only for equality tests against constants that share one target (`switchrecognition.cpp`). llvmnet lowers every LLVM `switch` to a chain of `bne.un`, so dispatch costs one compare per case. ffmpeg's decoder has 2,924 switches, 302 of them with 8 or more cases, and every program links musl's `printf_core`, whose switches go through the same chain.
- **Block copies.** `cpblk` and `initblk` with a constant size, and a constant byte for `initblk`, are unrolled up to 128 and 256 bytes on AVX hosts (64 and 128 with SSE only, 128 and 256 on ARM64; `getUnrollThreshold`); a variable byte gives `rep stosb`. llvmnet calls `Memory.Copy` and `Memory.Set` for every `llvm.memcpy` and `llvm.memset`. The tiered JIT inlines that path to the same unrolled moves, but NativeAOT and methods that cannot inline do not.
- **If-conversion.** RyuJIT never if-converts inside a loop (`ifconversion.cpp` checks the block weight and reachability) and requires both arms to cost at most 7. On x64 and ARM64, integer `Math.Min` and `Math.Max` are ordinary methods, not intrinsics, so they get the same treatment. For PF-15 and PF-18 this means a branch in IL stays a branch in a loop, and a `cmov` there comes only from an explicit arithmetic form.
- **Other shapes, no action needed.** Forward substitution folds a stored value into the next statement only, which is enough for llvmnet's typical GEP, load and use chains: address modes and memory operands form as they should. The `unaligned. 1` prefix llvmnet puts on every load and store changes nothing on x64. On ARM64 it stops the JIT from folding a load into a following extension and from using the acquire and release forms of volatile accesses. JIT settings are read from environment variables only (`jithost.cpp`), so an image cannot set them in `runtimeconfig.json`; crossgen2 and ILC accept them at compile time (`--codegenopt`).
- **ReadyToRun.** crossgen2 compiles a translated image without MinOpts. At run time the precompiled code is used and stays for the over-limit methods, because their Tier1 recompilation is discarded. A ReadyToRun image is specific to one operating system and architecture: the linux-x64 image fails with `BadImageFormatException` on macOS ARM64 and on Windows x64, where the IL-only image runs.
- **.NET 11.** The 11.0 RC2 runtime runs the subset below at the same speed as 10.0.14 (geometric mean 1.002); the limits above are unchanged in `main`.

## Experiments (2026-11-04)

Three CIL changes were implemented as switches in a scratch build of the compiler (`LLVMNET_EXPERIMENT`, patch in `artifacts/jit-patterns/`). For each comparison, one linked bitcode file was translated by the same compiler build with the switch off and on, and both were timed alternately with `scripts/ab-time.py`. Every output matched native.

| Experiment | Kernel or program | Before | After | Native |
| --- | --- | ---: | ---: | ---: |
| `CallCountingDelayMs=0` (no CIL change) | 22 benchmarks of the set, JIT, geometric mean | 1 | 0.911 | |
| | bullet, JIT | 2.572 s | 1.944 s | 1.364 s |
| | ffmpeg H.264 1080p, one thread, JIT | 2.956 s | 2.593 s | 1.436 s |
| `switch`: dense LLVM switches as CIL `switch` | 40-case bytecode interpreter, 256-op program, JIT | 0.580 s | 0.222 s | 0.144 s |
| | the same, NativeAOT | 0.474 s | 0.171 s | |
| | the same, 4,096 random ops (dispatch unpredictable), JIT | 0.560 s | 1.085 s | 0.904 s |
| `initonly`: global and constant address fields `static readonly` | PF-17-style loops over global arrays, JIT | 0.584 s | 0.513 s | 0.282 s |
| | the same, NativeAOT | 0.472 s | 0.475 s | |
| `switch` and `initonly` | 22 benchmarks of the set, JIT, geometric mean | 1 | 0.994 | |
| `cpblk` for constant-size `memcpy` | 48-byte copies, NativeAOT | 0.097 s | 0.087 s | 0.053 s |
| ReadyToRun of the image (crossgen2, linux-x64) | 22 benchmarks of the set, JIT, geometric mean | 1 | 0.847 | |
| | ffmpeg H.264 / HEVC, JIT | 2.908 / 3.344 s | 2.113 / 2.842 s | 1.436 / 2.365 s |
| | dhrystone, JIT | 0.165 s | 0.202 s | 0.090 s |

The tiering delay and ReadyToRun are the large, general gains, and they add up where both apply (bullet on 4 cores: 2.63 s by default, 1.89 s without the delay, 1.78 s with ReadyToRun as well). Both have losers. Without the delay, four programs are slower, three of them under 0.2 s (jpeg +12%, heapsort +9%, sha +8%, dhrystone +6%). ReadyToRun loses where a hot loop never leaves precompiled code (dhrystone +22%, fannkuch and heapsort +7%). The CIL forms are targeted: large on the code they fit (interpreter dispatch, loops over globals) and neutral on the set as a whole.

## Items

- [ ] **JP-01** (S, P1) Record [ADR-17](decisions.md#adr-17-readytorun-for-jit-deployments) and the milestone placement; done when the owner has accepted, amended or rejected both.
- [ ] **JP-02** (S, P1) Tiering in the emitted `runtimeconfig.json`: `CallCountingDelayMs` (0 or a small value), and `CallCountThreshold` if the set shows a gain. This is PF-06's follow-up. Done when: the whole benchmark set is measured with each candidate on this host and with 4 cores (`taskset`, the CI runner's size); the startup probe and the short programs (jpeg, sha, susan) are within their thresholds; the chosen value is in `runtimeconfig.json` and `docs/user/deployment.md`; and the baseline is updated.
- [ ] **JP-03** (M, P1) Switch lowering. A dense cluster of an LLVM `switch` becomes a CIL `switch` on the condition minus the cluster's lowest case. Dense means at least 4 cases and a range of at most 4 times the case count, as LLVM's jump tables require. A sparse switch becomes a binary search over its clusters instead of a linear chain, and conditions wider than 32 bits get a range check first. Done when: the IR semantics probes have switch cases on 8- to 64-bit conditions with negative, wrapping and sparse case values; the interpreter kernel is within 1.6 times native under the JIT and NativeAOT; and the benchmark set and the ffmpeg decodes do not regress. almabench lost 2.2% with this review's version (the 4-case switches in musl's `sin`, `cos` and `atan2`); the minimum case count is tuned against it. The random-dispatch case, which is slower like native's jump table, is recorded in the evidence file.
- [ ] **JP-04** (S, P1) Global and constant address fields marked `initonly`, which they are in fact: the type initializer writes each once, before any translated code runs. Thread-local globals are excluded. Done when: tests cover a translated method compiled with full optimization before `main` (a C++ constructor and `__attribute__((constructor))` reading globals, under `DOTNET_TieredCompilation=0`, `TC_QuickJitForLoops=0` and the default), NativeAOT and ReadyToRun builds, and system mode's symbol-resolved globals; the PF-17 kernel is measured; and the benchmark set does not regress. NativeAOT does not fold these fields, so PF-17's hoisting stays the fix there.
- [ ] **JP-05** (M, P1) A JIT budget per method, with BE-33 (denser IL) and BE-46 (the limits report). The parts this workstream adds:
  - `--diagnose-limits` models all five MinOpts triggers, the instruction count and local references among them, as `artifacts/jit-patterns`' `ilstats` tool does.
  - A value used once, later in its own block, stays on the evaluation stack when nothing between its definition and its use could reorder with it, as LLVM's WebAssembly backend does (`WebAssemblyRegStackify`). That saves a `stloc` and an `ldloc`, and so two of the 8,000 references.
  - Methods still over a limit are marked `AggressiveOptimization` in images that are not precompiled, which skips the second, discarded compilation (3.7% of the H.264 decode).

  The estimate from the decoder's statistics: 9 of the 26 methods over a limit after BE-33 would come under all of them. Done when the census of the benchmark set and ffmpeg is in the evidence with before and after counts, and outlining (BE-26) has the list of what remains over the limits.
- [ ] **JP-06** (M, P1) ReadyToRun for JIT deployments, as ADR-17 decides: crossgen2 run by the driver for one runtime identifier (`--readytorun <rid>`), with `LlvmNet.Runtime` in the same version bubble so its helpers can be inlined; the crossgen2 package provisioned like ILCompiler (TC-12's offline feed). The portable image stays IL-only. Done when: the benchmark set has a ReadyToRun column under the JIT, measured together with JP-02's setting; ffmpeg's H.264 decode shows no MinOpts method (`DOTNET_JitStdOutFile` summary); and the programs where ReadyToRun is slower (dhrystone, fannkuch, heapsort: hot loops that never leave precompiled code) are listed with a rule for when not to use it, or a partial image (JP-10).
- [ ] **JP-07** (S, P1) .NET 11. Run the benchmark set on the .NET 11 runtime under the JIT, and as NativeAOT with ILCompiler 11 once it is released, against 10.0.14. Propose to the owner whether translated images target `net11.0` or keep `net10.0` with roll-forward. Done when the table and the proposal are in the evidence file.
- [ ] **JP-08** (S, P2) `llvm.memcpy` with a constant size of at most 256 as `unaligned. cpblk`, and `llvm.memset` with a constant size and a constant byte as `initblk`; a variable byte, `llvm.memmove` and variable sizes keep the helpers. NativeAOT gains 10% on a small-copy kernel, the tiered JIT nothing (it already inlines `Memory.Copy` to the same code), and a variable-byte `initblk` (`rep stosb`) is slower than the helper under NativeAOT. Done when the memory semantics probes cover sizes 1 to 300 at every alignment, including equal source and destination, and the benchmark set does not regress under either engine.
- [ ] **JP-09** (S, P1) Gates: the benchmark report counts MinOpts methods per program (JIT summary), the nightly fails when a program of the set gains one, and the evidence file is updated at the milestone's exit.
- [ ] **JP-10** (M, P2) Partial ReadyToRun: precompile only the methods over the JIT's limits (crossgen2 `--partial` with a generated `.mibc` listing them), keeping Tier0, on-stack replacement and Tier1's constant folding for the rest; measured against JP-06's full image.
- [ ] **JP-11** (M, P2) Static profile data: LLVM's branch weights (`__builtin_expect`, `!prof` from `-fprofile-use`) as a `.mibc` file for ILC and crossgen2 (`--mibc`), which use it for block layout and inlining; measured on ffmpeg's `av_unlikely` paths under NativeAOT.

## Exit criteria for M12

JP-02 to JP-07 and JP-09 are done. The benchmark set's JIT geometric mean is lower than before the milestone, and no benchmark is slower beyond the nightly's thresholds, under the JIT or NativeAOT. The IR semantics probes and fuzzing are unchanged. The portable image stays one platform-neutral file, and the ABI freeze test passes unchanged.
