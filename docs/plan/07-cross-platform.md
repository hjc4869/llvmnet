# Workstream XP: Cross-platform execution

Prefix `XP`. Owner: unassigned. Milestone: [M6](README.md#m6-cross-platform).

## Current state (verified 2026-10-31)

- Portable images (`dotnet64-v2`) run on Linux x64, Linux ARM64, Windows x64 and macOS ARM64 under the JIT and as NativeAOT executables: the `tests/xp/` bundle (51 fixtures, 9 of them also NativeAOT) reproduces the native results on every host ([evidence/2026-10-31-m6-cross-platform.md](../evidence/2026-10-31-m6-cross-platform.md)). The host differences are documented in [dev/host-abi.md](../dev/host-abi.md#hosts-other-than-linux), the host matrix and NativeAOT provisioning in [toolchain.md](../toolchain.md#supported-hosts).
- The compiler itself runs only on Linux (ADR-05): the LLVM bridge is built by a Bash script, `libLLVM-22.so` is hard-coded, launchers are Unix shell scripts, and the system ABI is Linux x86-64 by design. NativeAOT executables for Windows and macOS are published on those hosts from the project `--aot-project` writes; `linux-arm64` is cross-published from Linux x64.
- The CI workflow has `xp` jobs on Windows, macOS and Linux ARM64 runners; they have not run on GitHub yet (FD-19).

## Items

- [x] **XP-01** (M, P0) Windows x64 under JIT: path translation in the host layer (`/` separators, drive letters, `realpath`), binary-only I/O (portable mode never translates line endings; documented), UTF-8 console, Ctrl-C as SIGINT, case-insensitive filesystem documented, `mmap` through `MemoryMappedFile`, no `fork`, timezone from `TimeZoneInfo`. A `tests/xp/` tag runs on a Windows runner. — **Done** (2026-10-31): drives appear as `/c/...`, `/tmp` is the temporary directory, directory links, Win32 errors mapped to errno, `sh.exe` for `/bin/sh`, the console switched to UTF-8; 183 of the 188 host-interface checks match Linux (the rest are mode bits and the zone abbreviation, documented), 51 of 51 bundle fixtures pass; `tests/xp/run.sh` runs on a Windows runner from the Linux job's bundle.
- [x] **XP-02** (M, P0) Linux ARM64 and macOS ARM64 under JIT: alignment (BE-15), saturating float conversions (BE-12), `Vector128` software fallbacks, atomics (BE-16), long double software paths; the `core` portable tag runs on ARM64 runners. — **Done** (2026-10-31): no code change was needed; macOS ARM64 matches Linux in all 188 host-interface checks, and the bundle's 51 fixtures (under-aligned access, 80-bit floats, 128-bit and floating atomics, contended threads) pass on macOS ARM64 and Linux ARM64. The ARM64 runners run the bundle rather than the `core` tag, because the compiler is Linux x64 only (ADR-05).
- [x] **XP-03** (L, P0) NativeAOT on `win-x64`, `osx-arm64` and `linux-arm64`: CI publishes and runs the portable C, C++ exception and thread fixtures; native toolchain requirements per platform are documented in TC-12. — **Done** (2026-10-31): `--aot-project <dir>` writes a relocatable NativeAOT project; the bundle's 9 projects (C, C++ exceptions and thread-local destructors, Fortran, threads, stdio) publish and pass on Windows x64 (MSVC), macOS ARM64 (Xcode) and linux-arm64 (cross-published); the per-host toolchains are in [toolchain.md](../toolchain.md#nativeaot-on-other-hosts).
- [ ] **XP-04** (L, P1) Compiler on Windows and macOS hosts: CMake build for the LLVM bridge (FD-09), per-OS LLVM library names, process spawning and quoting, temp directories, `.cmd` launchers, per-host packaging, and sourcing LLVM 22 binaries from official releases. If this slips, 1.0 ships the compiler for Linux only with outputs running everywhere ([ADR-05](decisions.md#adr-05-supported-platforms-for-10)).
- [x] **XP-05** (M, P1) Cross-publishing NativeAOT from Linux to `linux-arm64` with a cross toolchain, documented. — **Done** (2026-10-31): `--nativeaot --runtime-id linux-arm64` works with Debian's cross packages; the generated project selects `aarch64-linux-gnu-objcopy`.
- [x] **XP-06** (S, P0) Actionable startup errors on unsupported hosts (32-bit, big-endian, Mono, old runtimes) and a `llvmnet.runtimeconfig.json` that pins the framework band. — **Done** (2026-10-31): the emitted entry point calls `AbiContract.Diagnose` before the image's initializer and prints one `llvmnet:` line (verified on the Windows host's 32-bit runtime); `runtimeconfig.json` sets `rollForward: Minor`.
- [ ] **XP-07** (M, P1) Portability audit of the runtime: no `Vector<T>`, no `IntPtr.Size` assumptions beyond the 64-bit check, no OS branching outside the host layer, no reliance on `Console` encodings. — **In progress** (2026-10-31): random bytes no longer come from `RandomNumberGenerator`, which loads OpenSSL on Linux and aborted every image on a host without libssl; OS branches outside `Host/` are the two `AbiContract` and `SystemAbi` checks and `Toolchain` in the compiler. The `Vector<T>` and encoding audits are open.
- [x] **XP-08** (S, P1) Windows and macOS system-ABI modes are out of scope for 1.0; documented. — **Done** (2026-10-31): the host matrix in [toolchain.md](../toolchain.md#supported-hosts).
