# Workstream FT: Fortran runtime (flang-rt)

Prefix `FT`. Owner: unassigned. Milestones: [M2](README.md#m2-library-architecture-spike) (spike), [M5](README.md#m5-fortran-runtime) (delivery).

## Current state (verified 2026-10-30)

- 126 hand-written `_FortranA*` entry points across fourteen files in `src/LlvmNet.Runtime` (about 2,600 lines): formatted, list-directed, namelist, unformatted and direct I/O; descriptors; allocation; intrinsic assignment; a subset of reductions (`SUM` for four kinds only); `PACK`/`RESHAPE`/`TRANSFER`/`SPREAD`; random numbers; inquiries; date/time; array constructors; derived-type lifetime.
- Explicitly unsupported today: final procedures, defined I/O and defined assignment, general owned-component assignment, parameterized derived types, formatted direct access, segmented records, value stacks, `REAL(16)`, many editing descriptors, `MATMUL`/`MAXVAL`/`MINLOC`/`PRODUCT` and the other reductions not yet needed by a workload.
- Every installed SPEC Fortran entry passed in system mode with this runtime; portable failures are dominated by C/C++ library gaps rather than Fortran ones. Flang's upstream runtime was never compiled through llvmnet.

## Target architecture

Compile `flang-rt` (the LLVM 22 Fortran runtime, C++17) with llvmnet on top of musl and libc++ ([LC](02-portable-c-library.md), [CX](03-cxx-runtime.md)) and link it as `libflang_rt.runtime.a` bitcode. The hand-written runtime is deleted. `REAL(16)` stays rejected until [BE-14](01-compiler-backend.md) exists, so flang-rt is built without quad-precision support. Decision in [ADR-03](decisions.md#adr-03-fortran-runtime-strategy).

## Items

### Spike (M2)

- [x] **FT-01** (L, P0) Build `flang-rt/lib/runtime` from the LLVM 22 source tarball with `llvmnet-clang++ --runtime=portable` against the musl + libc++ sysroot, excluding quadmath. Run `print *, "hello"`, formatted real output, an `ALLOCATE`/`DEALLOCATE` loop, a namelist read, and `exchange2`-style array code. Record blockers (long double formatting, `__float128` references, large static tables, `std::` features) as BE/LC/CX items. — **Done** (`a71ed1c`): All 67 sources compile; 34 fixtures match native Flang (`tests/flang-rt.sh`).

### Delivery (M5)

- [x] **FT-02** (M, P0) Program glue: `_QQmain` entry, `_FortranAProgramStart`/`EndStatement`, command-line arguments, `STOP`/`ERROR STOP` exit codes, and environment handling (`FORT_CONVERT`, `FORT_FMT_RECL`, `NO_STOP_MESSAGE`) as flang-rt implements them. — **Done** (`1dc64f0`, `571d79f`): Flang emits `main`, which calls flang-rt's `_FortranAProgramStart`; `STOP`/`ERROR STOP`, arguments and `FORT_CONVERT`, `FORT_FMT_RECL`, `NO_STOP_MESSAGE` come from flang-rt in both modes (`tests/fortran-environment.sh`, `tests/fortran-convert.sh`, `tests/fortran-record-length.sh`).
- [x] **FT-03** (M, P0) I/O units over musl POSIX (`open`/`read`/`write`/`lseek`): console units 5/6/0, scratch files, `INQUIRE`, direct/stream access, asynchronous I/O reported as unsupported by flang-rt itself. — **Done** (`3f4ded0`, `571d79f`): flang-rt's units over musl (portable) and glibc (system); the unformatted, direct, stream, `INQUIRE`, `ENDFILE`, namelist and non-advancing tests pass in both modes under JIT and NativeAOT.
- [x] **FT-04** (M, P0) Numeric kinds: `REAL(10)` through flang-rt's long double paths exercises `Float80` heavily; `REAL(16)` produces a Flang-level diagnostic; integer kinds 1/2/4/8/16; `COMPLEX` of each supported kind; IEEE intrinsic modules. — **Done**: `REAL(10)` through `Float80` matches native Flang, `REAL(16)` is rejected by Flang ("REAL(KIND=16) is not an enabled type for this target"), integer kinds 1 to 16 and the complex kinds are covered by `tests/fortran.sh` and the conformance run (FT-06).
- [x] **FT-05** (M, P0) `scripts/build-portable-flang-rt.sh`: pinned source by hash, produce the runtime archive and install intrinsic `.mod` files (`iso_c_binding`, `iso_fortran_env`, `ieee_*`, later `omp_lib`) into the sysroot; the driver links the archive for Fortran inputs; delete `Fortran*.cs`. — **Done** (`1dc64f0`, `571d79f`): `scripts/build-flang-rt.sh` builds the archive for both modes as steps of `scripts/build-sysroot.sh`, the driver links it, and the C# Fortran runtime (`Fortran*.cs`, 2,603 lines) is deleted. Intrinsic modules come from the same Flang 22 installation (bundled by `--bundle-llvm`), which matches because the portable data layout is x86-64's.
- [x] **FT-06** (M, P0) Conformance: flang-rt's gtest unit tests compiled through llvmnet where feasible, `llvm-test-suite/Fortran` (including the gfortran test port), and the NIST FCVS F77 suite; publish pass rates. Expected to clear final procedures, defined I/O, PDTs and namelist completeness without llvmnet-specific code. — **Done** (`3f12932`, `0ef8ad7`): `tests/fortran-conformance.sh` runs FCVS (172 of 172 counted tests pass in portable mode) and the gfortran run tests of llvm-test-suite 22.1.8 (2,666 of 2,687, 99.2%), each compared with native Flang; failures are classified in `docs/evidence/2026-10-30-m3-m5.md`. flang-rt's own gtest unit tests are not run.
- [x] **FT-07** (M, P0) SPEC Fortran portable parity: exchange2, roms, wrf, cam4, pop2, bwaves, fotonik3d, cactuBSSN and the CPU 2026 Fortran entries; each failure becomes an item. — **Done** (LC-23 audit, `docs/spec-portable-limitations.md`): every Fortran rate entry passes in portable mode (bwaves, wrf, cam4, exchange2, fotonik3d, roms and the CPU 2026 rate entries) except cactuBSSN, whose C part relies on glibc's overlapping `sprintf` (native musl fails the same way), and PALM, which declares `open` with a fixed four-argument prototype (portable ABI). Every Fortran speed entry needs OpenMP (FT-08). BE-39 and BE-40 came from this item.
- [ ] **FT-08** (M, P1) Portable OpenMP: build LLVM's `openmp` runtime (`libomp`) over musl pthreads, provide `omp_lib` modules, validate `tests/c/openmp.c` and Fortran `DO CONCURRENT` host lowering. When `OMP_NUM_THREADS` is unset, the default thread count is `Environment.ProcessorCount`, which honors cgroup limits, affinity and `DOTNET_PROCESSOR_COUNT` (owner decision 2026-10-31). Extends [ADR-07](decisions.md#adr-07-portable-threading-model).
- [x] **FT-09** (S, P1) System mode: build the same flang-rt bitcode against host headers so both modes share one Fortran runtime, or document why the system mode keeps a separate build. — **Done** (`571d79f`): system mode links flang-rt built against the host's glibc and libstdc++ headers from `sysroot/system-linux-x64-v1`; without exceptions or RTTI it needs only the C++ bridge's `new`, `delete` and guards.

## Exit criteria for M5

FT-02 through FT-07 are done; FCVS and the `llvm-test-suite/Fortran` subset pass at or above 98% with failures classified; SPEC Fortran portable results match system mode, with parity as [ADR-14](decisions.md#adr-14-linux-identity-of-the-portable-target) defines it.
