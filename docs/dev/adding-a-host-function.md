# Adding a host function

The portable runtime reaches the operating system only through the host layer in `src/LlvmNet.Runtime/Host/`, whose contract is [host-abi.md](host-abi.md): Linux x86-64 system-call numbers, argument order, structure layouts and flag values, implemented over .NET APIs so that musl runs unmodified and behaves the same on every host. A missing service shows up as a program getting `ENOSYS` (or a documented `EPERM`) from musl. This is the procedure for implementing one.

1. **Find the call.** Read musl's wrapper for the libc function (`artifacts/vendor/src/musl-1.2.5/src/...`) to see which system call it makes and with which arguments, and check the number in `Host/Linux.cs` (`Linux.Syscall`). A number that is not in the enum returns `-ENOSYS` from the `default` arm of `HostSyscalls.Syscall`; a number listed in `HostSyscalls.Unavailable` is refused on purpose, with the errno and the reason the limitations page shows, and implementing it means removing it from that table.
2. **Add the number and its constants** to `Linux.cs`: the `Syscall` member, and any flag values or structure layouts the call uses, named as in musl's `arch/x86_64` headers. No other file may use a raw Linux constant.
3. **Implement it** in the `HostSyscalls` partial class file for its area (`HostFileSystem.cs`, `HostFiles.cs`, `HostProcess.cs`, `HostMemory.cs`, `HostThreads.cs`, `HostTime.cs`, ...), as a static method returning a non-negative result or `-errno`, and add its arm to the `switch` in `HostSyscalls.Syscall`. .NET exceptions are turned into errno values by `HostSyscalls.Errno`, the single mapping; on Linux an `IOException` keeps the kernel's errno. Use .NET APIs only: nothing may branch on the operating system outside `Host/`, and `HostPaths` handles the path forms of Windows.
4. **Compare with native.** Add the call to `tests/c/host-errors.c`, the conformance fixture of `tests/host.sh`, which runs natively and in portable mode and requires identical results and errno values for every check; include the failure cases (`EBADF`, `ENOENT`, `EACCES`, ...) as well as success. Where the behavior cannot be identical (a copy instead of a shared mapping, a hash instead of an inode number), document the difference in [host-abi.md](host-abi.md#behavior-that-differs-from-a-linux-kernel) and test what is promised.
5. **Other hosts.** The `tests/xp/` bundle runs a fixture set on Windows, macOS and Linux ARM64 against results recorded on Linux; add a fixture to `tests/xp/fixtures.tsv` when the call's behavior could differ by host, and describe a Windows difference in [host-abi.md](host-abi.md#hosts-other-than-linux).
6. **Update the contract.** Move the call from the "Not available" column to "Implemented" in the system-call table of [host-abi.md](host-abi.md), and regenerate [user/limitations.md](../user/limitations.md) with `tests/run.sh limitations` if it was in `Unavailable`. Implementing an additional call is compatible with the ABI tag; changing an entry point's signature or the meaning of an implemented call needs a new tag ([versioning.md](versioning.md#abi-tags)).

A new entry point (a function musl's port calls directly, like `__llvmnet_spawn`) is rarer: it needs a declaration in `ports/musl/arch/llvmnet`, a `[CExport]` method in the runtime with a scalar signature, a row in the entry-point table of host-abi.md, and a sysroot rebuild (`scripts/build-sysroot.sh`).
